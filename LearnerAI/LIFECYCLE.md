# Universal Lifecycle

The learner AI uses one recurring reasoning pattern across economy, construction, production, technology, military, and age transitions.

DEMAND
→ ADMISSIBILITY
→ CAPABILITY
→ FEASIBILITY
→ ACTION
→ WORLD-STATE CHANGE
→ WITNESS
→ RELEASE
→ REASSESS

## Demand

A persistent statement that something should be accomplished.

## Admissibility

The strategic or domain context still justifies the demand. A stale demand must not continue merely because it once existed.

## Capability

The domain identifies the means required to satisfy the demand.

## Feasibility

Engine-native conditions establish that the requested action can execute now.

## Action

The owning domain issues the engine action.

## World-state change

The engine may change the game state. The action itself is not evidence that it did.

## Witness

A fact observable in the resulting world proves completion or failure.

## Release

The demand is cleared, transitioned, or cancelled according to the witness and lifecycle rules.

## Reassess

Information and current state feed Strategy and domain modules again. The system is a feedback loop, not a one-shot build order.

## Blocked lifecycle

If feasibility remains false, preserve legitimate persistent intent while allowing transient cooldown/backoff and domain recovery. Do not convert every persistent requirement into an accumulating retry counter.

## Teaching invariant

For every important behavior, the learner should be able to point from the demand to the witness and explain every step between them.
