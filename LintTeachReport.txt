ByzMetaTeacher lint repair record
================================

Forensic baseline
-----------------
The historical ERR6002 report in commit 12e29502cceb40c6e584f7e227e80241afc0b5d2 contains 210 diagnostic entries. Those entries are not 210 independent oversized rules.

The historical source has a malformed initialization rule beginning at line 172. It contains 23 runtime actions plus its fact, and it also contains literal Markdown fence lines. That rule is unambiguously over the community-compatible 16-element limit and over DE's 32-element limit once its commands/operators are counted. The Markdown fences are also invalid .per source.

The remaining ERR6002 line ranges in that historical report map, in the same repository snapshot, to rules whose actual command counts are below both 16 and 32. They therefore cannot be treated as independently verified rule-too-long defects from that snapshot. They are retained as historical diagnostics, not as a list of 210 separate code repairs.

Community standard used
-----------------------
1. AIRef documents 32 elements per rule in DE and 16 in UP; the defrule and => separator do not count. Elements include commands and logical operators.
2. Established community practice is to keep rules comfortably below the DE ceiling, and often at or below 16 when practical, using state goals or split rules rather than giant condition trees.
3. Binary logical operators such as and/or take two direct child facts. Larger OR sets must be nested or, where appropriate, represented as state goals.
4. Goals are used as state variables to reduce repeated condition trees and keep strategy/production consumers readable.

Repairs
-------
1. The oversized initialization rule was split into three one-shot initialization rules. This preserves the teaching architecture while reducing the command load.
2. All accidental Markdown fences were removed from .per source.
3. The existing threat-state architecture was retained rather than replacing it with a new controller.
4. Every multi-child OR introduced by the prior repair was converted to binary nested OR form. No n-ary direct OR remains.
5. The strategy -> unit-goal -> production -> training teaching pipeline remains intact.
